# z-kb 1.1.0：默认 persistent + 默认 z-graph + fail-fast（破坏性变更公告）

> 卡片：TASK-20261012-023（lead 仓 `002_项目需求/002_任务队列/`）
> 口径来源：特性需求 `002_项目需求/001_特性需求/010_持久化收尾_zkb_zvector_zgraph`，D1 拍板
> —— **默认值翻转按破坏性变更发 1.1.0 显式公告，不搞静默切换**。
> 纪律：**动的是装配与文档，引擎一行不改**（z-vector / z-graph / z-kb 的引擎实现都没碰）。

## 结论先行

| 项 | 旧默认（1.0.x） | 新默认（1.1.0） | 显式回旧档 |
|---|---|---|---|
| 向量存储 | `in-memory`（内存，重启丢） | `persistent` ⇒ `PersistentVectorStore`（落盘，重启不丢） | `zkb.vector.storage-type=in-memory` |
| 持久化向量**装不上**时 | **静默回落**内存向量，服务照常起 | **启动失败**，错误信息带修复指引 | 无（这正是本次要改的行为） |
| 图谱存储 | `JsonFileKnowledgeGraphStore`（JSON 文件，重启不丢） | `ZGraphKnowledgeGraphStore`（z-graph 引擎，**进程内图谱，重启不保留**） | `zkb.graph.engine=json` |
| 图谱引擎开关 | 无 | 新增 `zkb.graph.engine`（`zgraph` 默认 / `json`） | `zkb.graph.engine=json` |
| 本地状态目录 | 向量 `./data/zvector`（相对 CWD）／图谱 `~/.zkb/graph`／文档 `~/.zkb/zkb.json` | 统一收敛到 `~/.zkb/`：`vector/`、`graph/`、`zkb.json` | `zkb.vector.data-dir` / `zkb.graph.path` / `zkb.storage.path`（均支持 `~` 展开） |
| `dev` profile | 无专门口径 | **回落成 1.0.x 默认口径**：内存向量 + JSON 图谱（对齐 z-lc 的 dev H2 家族惯例） | — |

| 配置键 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `zkb.vector.storage-type` | `persistent` / `in-memory` | `persistent` | 其它取值**启动失败**（带修复指引） |
| `zkb.vector.data-dir` | 绝对路径（支持 `~`） | `~/.zkb/vector` | 不可写 ⇒ 启动失败 |
| `zkb.graph.engine` | `zgraph` / `json` | `zgraph` | 其它取值**启动失败**（带修复指引） |
| `zkb.graph.path` | 绝对路径（支持 `~`） | `~/.zkb/graph` | 仅 `engine=json` 时生效 |
| `zkb.storage.path` | 绝对路径（支持 `~`） | `~/.zkb/zkb.json` | D3：文档仓库仍默认 JSON 持久化 |

## 为什么是 fail-fast（而不是回落）

1.0.x 的回落是**静默**的：持久化向量装不上 ⇒ 打一条 WARN ⇒ 回落内存向量 ⇒ 服务正常起来。
后果是「服务健康、向量写进了内存、重启全丢」，现场从监控上看不出任何异常 ——
这类故障要等到重启后用户投诉才发现。1.1.0 改成**启动失败 + 修复指引**：

```
z-kb 启动失败：持久化向量存储不可用（zkb.vector.storage-type=persistent, data-dir=/data/zkb/vector）
—— 类 com.zifang.z.vector.storage.PersistentVectorStore 不在 classpath 上（依赖 io.github.yuku123:z-vector-storage 没被引入）。
修复指引：① 确认依赖已引入 io.github.yuku123:z-vector-storage（z-kb-vector 的传递依赖）；
② 确认 data-dir 目录存在且当前进程用户可写（ls -ld / chmod u+w / chown）；
③ 若确需退回内存向量，显式配置 zkb.vector.storage-type=in-memory（注意：内存向量重启后不保留）。
```

## 消费方升级说明（z-opc 等）

1. **先看 data-dir 能不能写**：向量默认落 `~/.zkb/vector`（容器里就是 `$HOME` 下的目录）。
   容器没有可写 HOME / 没挂卷 ⇒ 启动会失败（这是有意的：失败要响）。
   显式指路：`zkb.vector.data-dir=/data/zkb/vector`（挂可写卷）。
2. **图谱默认从「JSON 文件」变成「进程内 z-graph」** ⇒ **重启后图谱不保留**。
   要保留旧行为请显式配 `zkb.graph.engine=json`（数据目录默认 `~/.zkb/graph`）。
   存量 JSON 文件在 `engine=json` 下原地继续读写，无需迁移。
3. **依赖树多了 `z-vector-storage`**（`PersistentVectorStore` 所在坐标）⇒ fat jar 体积相应变化。
4. **不需要改代码**就能拿到新行为；想留在旧口径只需两行配置（见上表「显式回旧档」）。
