## 一、一句话结论

**z-***REMOVED*** 的「物料→编译→检索→评测」主干是真实能跑通的工程，不是 PPT 架构**；但它是「两套数据栈并行」的中间态，v1 域检索质量弱、问答只在旧域，离「统一接入源→问得出答案」的产品目标还差一次收拢。

## 四、本轮挖出并修复的真 bug（4 处）

1. **bootstrap 版本欠账**：parent/版本停在 1.0.1，离线构建直接失败 → 对齐 1.1.0。
2. **全包扫描破坏条件装配**：`@ComponentScan("com.zifang.z.***REMOVED***")` 把 `@AutoConfiguration` 当普通 `@Configuration` 抢先注册，类级 `@ConditionalOnBean(DataSource)` 扫描期恒 false → 18 个 v1 控制器全部消失。改为只扫 `web.config`/`web.controller` + 自动装配。
3. **GraphController bean 名冲突**：新旧两个控制器同名 `graphController` → v1 侧显式命名 `***REMOVED***GraphV1Controller`。
4. **standalone 无数据源 + 无日志 provider**：没配 datasource（资源域整块不装配）；父链排除了 logging starter 且无 SLF4J 实现（`--debug` 条件报告全丢）→ 补 H2 + log4j2 三件套。

## 五、本轮实测发现的新缺陷（未修，按严重度）

**架构级**
- **两套数据栈并行**：v1 物料域走 JDBC/H2，旧工作台域走 `~/.***REMOVED***/***REMOVED***.json` + 内存索引。v1 灌的物料旧域看不见，webhook 口喷 v1 看不见。**v1 域没有 chat 端点**——问答/图谱召回/三路融合只在旧域。这是「统一接入源」目标的最大结构性障碍。
- **v1 物料域的检索是单路 dense**（local-hash-ngram-v1，384 维中文二元组哈希），没有 BM25/图谱参与；旧域的三路 RRF 没有接到 v1 的物料上。

**功能级**
- **frontmatter 没剥离**：`Default***REMOVED***MaterialParser` 是纯 UTF-8 直读，`MarkdownParser`（有 frontmatter 解析）只服务旧域 → Wiki 要点第一段是 `--- title: ... ---`，summary 也是 frontmatter。
- **概念节点名带 `.md`**：图谱把文件名直接当概念名（"会议口喷速记.md"）。
- **问句/FAQ 机械模板**：「X.md是什么？」「X.md包含哪些内容？」——标题拼接，无信息量。
- **中文分词粗糙**：旧域实体抽取把「接入源」切成「接入」「入源」两个概念。
- **死字段**：`SearchHit.documentTitle`/`matchedKeywords`、`ChatResponse.messageId` 全仓无赋值点，纯装饰。
- **评测参数报错误导**：`expectedBehavior` 只接受 ANSWER/REFUSE，传中文报笼统的「评测参数不合法」。
- **全局异常处理器自身会炸**：`WebExceptionHandler.handleOther(Exception, HandlerMethod)` 的 `HandlerMethod` 参数在部分场景无法解析，兜底处理器失效（日志可见 secondary exception）。
- 小口径：`/api/***REMOVED***/documents/count` 返回 `[]` 而统计接口有值；Git 同步失败回执的 failed 计数需再核。

## 六、水平定位

**工程成熟度：可运行的单机知识库中台雏形，约 7/10**
- 强：模块边界清晰（11 库 + bootstrap）、编译流水线带里程碑与产物登记簿、评测域有真实的指标体系和坏例闭环、错误路径设计诚实（NOT_CONNECTED 不冒充、假令牌如实报错）。
- 弱：检索质量是最大短板（本地 hash 向量无语义能力），问答与物料域割裂，解析链路对 Markdown 基础设施（frontmatter）欠账。

**产品成熟度：可用度 ~4/10**
- 能存、能编、能查（词面）、能评；但「随口一问就能得到带引用的好答案」这个核心体验，目前在 v1 域做不到，在旧域是抽取式兜底（配 LLM 前）。

## 七、下一步建议（优先级序）

1. **打通两栈**：把旧域 HybridSearcher（三路 RRF）接到 v1 物料的 JDBC 检索块上，问答端点进 v1 —— 这是投入产出比最高的一刀。
2. **换真 embedding**：`local-hash-ngram-v1` 只有词面哈希，接一个本地小模型或 API embedding，「standalone 起不来的原因」这类语义问题才能召回。
3. **解析器升级**：`Default***REMOVED***MaterialParser` 复用 `FrontmatterParser`，frontmatter 进 meta 而非正文。
4. **修评测报错口径**：`expectedBehavior` 校验失败时返回「expectedBehavior 只能是 ANSWER/REFUSE」而非笼统 400；顺手修 `handleOther` 的 `HandlerMethod` 解析问题（改为 `@ExceptionHandler(Exception.class)` 不带 HandlerMethod 参数或拆两个方法）。
5. **补回归**：本轮 4 处启动类修复（bootstrap 契约/bean 名/条件装配/datasource+日志）都值得固化成测试。
