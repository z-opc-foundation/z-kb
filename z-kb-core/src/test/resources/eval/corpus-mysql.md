# MySQL 索引优化

MySQL 的 InnoDB 存储引擎使用 B+ 树结构组织主键索引。聚簇索引的叶子节点存放整行数据，
因此主键查询无需回表。覆盖索引让查询可以在索引树上完成，避免额外的随机 IO。

## 最左前缀原则

联合索引 (a, b, c) 只能从最左列开始匹配。查询条件从 b 列开始会直接导致索引失效，
退化为全表扫描。在高并发场景下这类退化会把连接池迅速打满。

## 索引失效的常见写法

对索引列施加函数运算、隐式类型转换、前导模糊匹配 LIKE '%x' 都会让索引失效。
把 varchar 列与数字比较会触发隐式转换，等价于对列套了一层 CAST。

## 慢查询日志

slow query log 记录超过 long_query_time 的语句。开启后应配合 pt-query-digest 做聚合分析，
而不是逐条肉眼看日志文件。
