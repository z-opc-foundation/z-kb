
# Future Brain 开发约束

本项目使用 React 19、TypeScript、Vite、Ant Design 与 React Router。优先做保持模块边界的小范围修改；禁止为了实现当前需求而进行无关重构。

具体 UI 与组件实现规范（如新增表格规范）见 [doc/coding-standards.md](doc/coding-standards.md)，开发时必须一并遵循。

## 开始修改前

1. 先阅读目标功能、所属服务、路由注册和相邻测试。
2. 先搜索已有的接口、类型、组件、Hook 和工具函数，再决定是否新增。
3. 保留工作区中与当前需求无关的改动，不删除测试、依赖、脚本或已有行为来规避问题。
4. 保持 TypeScript 严格类型；跨目录导入使用 `@/` 别名。

## 开发守则

1. 一个组件只承担一个清晰职责。页面的区块、表格列定义、弹窗、复杂表单、阶段面板和独立交互应拆成命名组件；数据加载、状态编排和副作用应拆入 Hook。禁止把多个独立功能持续堆进单个 `index.tsx`，形成数千行甚至上万行文件。
2. 拆分以职责、复杂度和可读性为准，不为了凑行数拆出只做一层透传、没有语义的文件。相关的小型展示逻辑可保持在同一组件内。
3. Ant Design 已提供的组件、图标、表单能力、反馈能力和布局能力必须优先直接使用。只有现有 API 无法满足产品交互或视觉要求时，才封装或自建组件，并说明缺口。
4. 优先选择最直接、可读的实现：明确的数据流、短小的命名函数和局部状态。避免为一次性需求引入多层包装、过度抽象、无必要的配置驱动或间接跳转。
5. 复用必须基于稳定的共同需求。只在一个地方使用的逻辑先保持局部；出现明确的第二个使用场景后，再提取共享抽象。
6. 每次提交应让读者能快速回答“数据从哪里来、状态由谁维护、交互触发什么”。无法快速说明时，继续拆分或简化实现。

## 代码归属

| 改动类型 | 归属位置 |
| --- | --- |
| HTTP 传输、响应解包、登录失效、网络错误 | `src/services/http.ts` |
| 后端能力及其请求/响应类型 | 对应的 `src/services/<domain>.ts` |
| 跨领域业务类型 | `src/types/domain.ts` |
| 页面专属状态、数据加载、交互编排 | `src/pages/<feature>/hooks/use-*.ts` |
| 有明确跨页面复用价值的 UI | `src/components/<component>/` |
| 仅页面使用的 UI | 所属页面或其 `components/` 目录 |
| 路由与菜单元数据 | `src/routes/index.tsx` |
| PC 壳层、登录用户、顶部导航 | `src/layout/` |
| 移动端页面与辅助逻辑 | `src/pages/mobile/` |

禁止页面功能之间直接互相导入页面组件。确认存在稳定的共同所有者后，再抽取共享组件、Hook、类型或工具函数。

服务模块按领域维护，不能成为万能文件。Code Agent 合同归属 `src/services/agent.ts`；通用聊天消息归属 `src/services/chat.ts`。复用类型时从其所有者导入，不重复声明或恢复已移除的服务模块。

## 接口边界

1. 仅通过 `src/services/http.ts` 导出的 `request`、`downloadFile`、`buildApiUrl` 调用后端。
2. 禁止在页面或组件中直接调用 `axios`、`fetch`，手动拼接 `/kapi`，或手动解包 `ApiEnvelope`。
3. 每个接口提供带类型的服务函数；路径参数使用 `encodeURIComponent`，查询参数使用 `URLSearchParams`。
4. 请求和响应类型放在对应服务函数附近，优先复用已导出的类型。
5. `RequestError` 与 HTTP 拦截器负责登录跳转、统一响应、网络异常和 504 判断；UI/Hook 仅处理本功能的提示与恢复。
6. 异步加载必须在 `finally` 中释放 loading 状态。

## 路由与布局

1. 所有可导航页面必须在 `src/routes/index.tsx` 注册；`appRoutes` 是菜单来源，`allRoutes` 是渲染来源。
2. 已登录 PC 页面默认使用 `app` 布局；不应出现桌面页头的页面使用 `layout: 'blank'`，包括移动端和中转页面。
3. 登录态初始化、导航壳层和全局路由逻辑属于 `src/layout/index.tsx`，业务页面通过 `Outlet` 渲染。
4. 重定向和设备跳转必须保留必要 query 参数；只有中转地址不应保留在历史记录时才使用 `replace`。
5. 异步页面必须有明确的 loading、空、错误和成功状态。导航后发生延迟时，立即给出加载反馈，不能长时间展示旧页面内容。
6. 新增懒加载路由必须有邻近的 `Suspense` fallback；不要仅为形式引入懒加载。

## 页面状态与 UI

1. 状态默认放在页面本地；只有多个独立页面确实共用时才提升。
2. 非简单的数据加载和交互编排拆入命名 `use-*.ts` Hook，页面组件以展示和组合为主。
3. 依赖可能变更的异步 effect 必须防止过期更新；轮询、计时器、订阅和监听器必须清理。
4. 复用 Ant Design 与特性内既有的 `App.useApp()` 反馈方式。未经明确架构决策，不引入新的 UI 框架或全局状态库。
5. 样式放在所属特性或组件中，沿用本地 `.less` 或 `.css` 格式；仅全局规则可以使用全局选择器。
6. PC 和移动端交互保持独立，只复用无状态展示、服务合同和真正通用的工具函数。

## 改动纪律

1. 避免顺带重写大型既有模块；必要时用 Hook、组件或服务函数隔离新行为。
2. 迁移调用方时保留兼容路径，全部迁移后在同一改动中移除旧路径和全部引用。
3. 未经明确需求，不修改代理、base path、SSO、包脚本、测试工具或构建配置。
4. 禁止用 `any`、`@ts-ignore`、不安全断言或关闭类型检查来掩盖问题；使用可选字段、联合类型、类型守卫或 `unknown` 建模不确定性。

## 验证

使用 `fnpm` 管理依赖。按改动风险选择验证，并如实报告无法运行的原因：

| 改动类型 | 最低验证 |
| --- | --- |
| 服务或类型合同 | 搜索全部引用，运行 `fnpm run typecheck` |
| Hook、工具或业务转换 | 增加/更新聚焦 Vitest 用例，运行 `fnpm test` |
| 路由、布局或用户流程 | `fnpm run typecheck`；有相关覆盖时运行 `fnpm run test:e2e` |
| 样式或移动端响应式行为 | 启动开发服务，检查桌面和移动端渲染 |
| Vite 或构建配置 | `fnpm run build` |

依赖解析失败应与代码错误分开报告；不得通过削弱 TypeScript、移除测试或删除依赖来绕过。
